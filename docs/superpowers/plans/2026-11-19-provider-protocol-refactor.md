# 供应商与请求协议拆分

目标：将可维护的供应商记录与固定的 SDK 协议适配器分离，让 xAI、智谱和自定义供应商无需增加数据库枚举或代码分支。运行时仅接受新数据结构，不提供旧字段别名或回退。

实施顺序：

1. 先锁定现有 Chat / Responses / Anthropic / Gemini 的请求路径、鉴权、查询参数及模板参数行为；4 个请求回归测试已在改造前通过。
2. 增加 `check_providers`（标识、名称、图标、可选官方状态来源），用外键替换原有供应商枚举；检测配置显式保存 `protocol`，模型和模板保留供应商一致性约束。
3. 仅按协议创建 SDK；供应商身份贯通配置加载、历史快照、公开 API 与界面。未设置官方状态来源的供应商不附带其他厂商状态。
4. 直接更新 public / dev 最终初始化结构；项目没有存量数据，不提供数据迁移、回填或历史结构支持。
5. 补充任意供应商、显式协议、Gemini 自定义域名/查询参数、元数据关联与数据库约束验证；运行测试、lint、类型检查和构建。

范围：本仓库的监测和数据结构；独立管理后台源码不在当前工作区。供应商可通过 Supabase Studio 维护，配套后台需要使用新的表与字段。README 不记录重构过程。

验证限制：按用户要求，本轮不启动 Docker 容器、不运行数据库迁移或数据库回归脚本；只执行单元测试、lint、类型与构建检查。数据库约束保留独立的初始化回归脚本，供后续验证。
